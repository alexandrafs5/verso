# SPEC 14 — Catalog tables (M3.2)

> **Status:** Implemented
> **Depends on:** SPEC 06, SPEC 13
> **Date:** 2026-11-24
> **Objective:** Add the Work, Edition, Author, WorkAuthor, Genre, WorkGenre and Series tables (ARCHITECTURE §5.3) in one forward-only migration, tested on real Postgres.

## Scope

**In:**

- Prisma enums `WorkSource`, `CatalogStatus`, `ReviewStatus`, `EditionFormat`.
- Prisma models `Work`, `Edition`, `Author`, `WorkAuthor`, `Genre`, `WorkGenre`, `Series`, with all columns listed in §5.3, including the manual-book columns (`createdById`, `mergedIntoId`, `reviewStatus`, `catalogStatus`).
- One forward-only migration.
- Integration tests on real Postgres for unique keys, join tables, delete rules and the merge self-relation.
- ROADMAP: tick M3.2.

**Out of scope (for future specs):**

- Repositories, services, controllers and endpoints for these tables (M3.3, M4.2).
- Persisting works on add to library (M4.2).
- `UserBook`, `ProfileFavorite`, `Review` and any table that references `Work` or `Edition` (M4.1 and later).
- Genre seed data and subject-to-genre mapping (M3.4).
- Manual book creation, review flow and admin screens (M10).

## Data model

Ids are UUID v7 strings generated by the app, as in SPEC 06 and SPEC 13. No `@default` on ids.

```prisma
enum WorkSource    { OPEN_LIBRARY MANUAL }
enum CatalogStatus { PUBLIC PRIVATE }
enum ReviewStatus  { NONE PENDING APPROVED REJECTED MERGED }
enum EditionFormat { PAPERBACK HARDCOVER EBOOK OTHER }

model Work {
  id               String        @id
  title            String
  subtitle         String?
  description      String?
  firstPublishYear Int?
  olWorkKey        String?       @unique
  source           WorkSource    @default(OPEN_LIBRARY)
  catalogStatus    CatalogStatus @default(PUBLIC)
  reviewStatus     ReviewStatus  @default(NONE)
  createdById      String?
  createdBy        User?         @relation("WorkCreatedBy", fields: [createdById], references: [id], onDelete: SetNull)
  mergedIntoId     String?
  mergedInto       Work?         @relation("WorkMerge", fields: [mergedIntoId], references: [id], onDelete: SetNull)
  mergedFrom       Work[]        @relation("WorkMerge")
  seriesId         String?
  series           Series?       @relation(fields: [seriesId], references: [id], onDelete: SetNull)
  seriesPosition   Decimal?      @db.Decimal(6, 2)
  editions         Edition[]
  authors          WorkAuthor[]
  genres           WorkGenre[]
  createdAt        DateTime      @default(now()) @db.Timestamptz(3)
  updatedAt        DateTime      @updatedAt @db.Timestamptz(3)

  @@index([seriesId])
  @@index([createdById])
  @@index([reviewStatus])
}

model Edition {
  id           String        @id
  workId       String
  work         Work          @relation(fields: [workId], references: [id], onDelete: Cascade)
  isbn10       String?
  isbn13       String?       @unique
  title        String
  publisher    String?
  publishYear  Int?
  language     String?       // ISO 639-1
  pageCount    Int?
  format       EditionFormat @default(OTHER)
  coverUrl     String?
  olEditionKey String?       @unique
  source       WorkSource    @default(OPEN_LIBRARY)
  createdById  String?
  createdBy    User?         @relation("EditionCreatedBy", fields: [createdById], references: [id], onDelete: SetNull)
  createdAt    DateTime      @default(now()) @db.Timestamptz(3)
  updatedAt    DateTime      @updatedAt @db.Timestamptz(3)

  @@index([workId])
  @@index([isbn10])
}

model Author {
  id          String       @id
  name        String
  bio         String?
  birthYear   Int?
  deathYear   Int?
  photoUrl    String?
  olAuthorKey String?      @unique
  works       WorkAuthor[]
  createdAt   DateTime     @default(now()) @db.Timestamptz(3)
  updatedAt   DateTime     @updatedAt @db.Timestamptz(3)
}

model WorkAuthor {
  workId   String
  authorId String
  position Int    @default(0)
  work     Work   @relation(fields: [workId], references: [id], onDelete: Cascade)
  author   Author @relation(fields: [authorId], references: [id], onDelete: Restrict)

  @@id([workId, authorId])
  @@index([authorId])
}

model Genre {
  id    String      @id
  slug  String      @unique
  name  String
  works WorkGenre[]
}

model WorkGenre {
  workId  String
  genreId String
  work    Work   @relation(fields: [workId], references: [id], onDelete: Cascade)
  genre   Genre  @relation(fields: [genreId], references: [id], onDelete: Restrict)

  @@id([workId, genreId])
  @@index([genreId])
}

model Series {
  id           String   @id
  name         String
  olSeriesKey  String?  @unique
  works        Work[]
  createdAt    DateTime @default(now()) @db.Timestamptz(3)
  updatedAt    DateTime @updatedAt @db.Timestamptz(3)
}
```

`User` gains the back-relations `createdWorks` and `createdEditions`. No column on `User` changes.

Conventions:

- `isbn13` and `olEditionKey` are unique. Postgres allows many `NULL` values in a unique column, so manual editions without them are fine.
- `seriesPosition` is decimal to allow "0.5" and "1.5" novellas.
- A work with `mergedIntoId` set is read as a redirect. The merge logic is not in this spec.

## Implementation plan

1. Add the four enums and the seven models to `apps/api/prisma/schema.prisma`, with the back-relations on `User`. Verify: `pnpm --filter api prisma validate`.
2. Run `pnpm db:migrate` with the name `catalog_tables`. Read the generated SQL. Verify: it creates only the new enums, tables, indexes and foreign keys.
3. Add `apps/api/test/catalog-schema.integration.spec.ts` (match the folder and naming of existing integration tests). Cover the acceptance criteria below. Verify: `pnpm --filter api test`.
4. Tick M3.2 in `ROADMAP.md`. Run `pnpm lint && pnpm typecheck && pnpm test`.

## Acceptance criteria

- [x] `pnpm db:migrate` applies cleanly on an empty database and on the current dev database.
- [x] The migration creates only the seven new tables and four new enums. No existing table changes.
- [x] Two works with the same `olWorkKey` fail. Two works with `olWorkKey` null succeed.
- [x] Two editions with the same `isbn13` or the same `olEditionKey` fail. Two editions with those values null succeed. Two editions with the same `isbn10` succeed.
- [x] Two authors with the same `olAuthorKey` fail. Two genres with the same `slug` fail. Two series with the same `olSeriesKey` fail.
- [x] A duplicate (`workId`, `authorId`) in `WorkAuthor` fails. A duplicate (`workId`, `genreId`) in `WorkGenre` fails.
- [x] Deleting a work deletes its editions, `WorkAuthor` rows and `WorkGenre` rows.
- [x] Deleting an author or a genre that still has a work fails.
- [x] Deleting a series sets `seriesId` and keeps `seriesPosition` untouched on its works (position stays, series is null).
- [x] Deleting a work that others merged into sets their `mergedIntoId` to null.
- [x] Deleting a user sets `createdById` to null on their works and editions.
- [x] `seriesPosition` stores `1.5` and reads it back as `1.5`.
- [x] `Work` defaults: `source` OPEN_LIBRARY, `catalogStatus` PUBLIC, `reviewStatus` NONE. `Edition.format` defaults to OTHER.
- [x] `pnpm lint && pnpm typecheck && pnpm test` pass.
- [x] M3.2 is ticked in `ROADMAP.md`.

## Decisions

- **Yes:** quick definition. The user asked for a short spec, so Phase 2 questions were answered with the recommended defaults below. They can be changed before approval.
- **Yes:** include the manual-book columns now (`createdById`, `mergedIntoId`, `reviewStatus`, `catalogStatus`, MANUAL source). Manual books are F1 (ROADMAP M10), and adding columns later costs another migration.
- **No:** `UserBook` and its `Edition` reference. They belong to M4.1.
- **Yes:** `ON DELETE CASCADE` from `Work` to `Edition`, `WorkAuthor` and `WorkGenre`. Rows have no meaning without the work.
- **Yes:** `ON DELETE RESTRICT` from join tables to `Author` and `Genre`. An author or genre should not vanish under a work.
- **Yes:** `ON DELETE SET NULL` for `seriesId`, `mergedIntoId` and `createdById`. The work survives its series, its merge target and its creator.
- **Yes:** `isbn10` has a plain index, not a unique one. Old ISBN-10s are reused across editions in practice.
- **Yes:** `olSeriesKey` unique and nullable. Series are local data, so most rows have no key.
- **No:** seed `Genre` rows. M3.4 defines the subject mapping, so seeding now would guess the list.
- **Yes:** `seriesPosition` as `Decimal(6,2)`.
- **Yes:** ids generated by the app (UUID v7), no DB default, matching SPEC 06 and SPEC 13.
- **Yes:** `Edition.source` reuses the `WorkSource` enum.
- **Yes:** `Author` and `Series` carry `createdAt` and `updatedAt`. §5.3 lists none for them, but the convention in §5.3 says timestamps exist. `Genre` and the join tables have none.

## Risks

| Risk | Mitigation |
| ---- | ---------- |
| §5.3 lists no `createdAt` for some tables | Added by convention. If wrong, change before approval, since migrations are forward-only once merged |
| A later table needs a column on these tables | Adds a new forward-only migration |

## What is **not** in this spec

- Repositories, services, endpoints or any web change.
- Persisting works or editions on add to library.
- `UserBook`, `Review`, `ProfileFavorite` and other tables that reference `Work`.
- Genre seed data or mapping.
- Manual book creation, review and merge logic.
