# SPEC 13 — CatalogProvider and OpenLibraryProvider (M3.1)

> **Status:** Approved
> **Depends on:** SPEC 01, SPEC 08
> **Date:** 2026-11-24
> **Objective:** Add the `CatalogProvider` interface, an `OpenLibraryProvider` (search, work, editions, ISBN, author) backed by a Postgres `ExternalCache`, and an in-memory fake, all tested against recorded fixtures.

## Why this spec exists

Every M3 endpoint and screen reads books through Open Library, which is slow, rate-limited and outside our control (ARCHITECTURE §7). This spec isolates that dependency behind an interface, so services and tests never touch the network. It also creates `ExternalCache`, because M3.1 needs it and neither M3.1 nor M3.2 listed it in ROADMAP. The same table serves the stats cache later (§5.6).

## Scope

**In:**

- `CatalogProvider` interface (§7) and the external types `WorkSearchResult`, `ExternalWork`, `ExternalEdition`, `ExternalAuthor`.
- `OpenLibraryProvider`: five methods, 8 s timeout, `User-Agent: Verso/1.0 (<contact>)`, cover-ID URLs, Zod validation of Open Library responses.
- `ExternalCache` Prisma model, forward-only migration, `ExternalCacheRepository` (Prisma only) and the `ExternalCacheStore` interface it implements.
- Cache TTLs: search 1 day; work, editions, ISBN and author 30 days.
- Typed errors `CatalogNotFoundError` and `CatalogUnavailableError`.
- `InMemoryCatalogProvider` and `InMemoryExternalCache` fakes for later tests.
- `CatalogInfraModule` exporting `CATALOG_PROVIDER` and wired into `AppModule`.
- Env `OPEN_LIBRARY_CONTACT` loaded and validated in `catalog-env.ts`.
- Fixtures recorded once from the real Open Library, trimmed and committed.
- ROADMAP: tick M3.1 and note under M3.2 that `ExternalCache` already exists. ARCHITECTURE §7: note typed errors, fail-open cache and the env var.

**Out of scope (for future specs):**

- `@nestjs/throttler` (M3.0).
- Catalog tables Work, Edition, Author, WorkAuthor, Genre, WorkGenre, Series (M3.2).
- Controllers, DTOs, Zod API schemas in `packages/shared`, problem+json mapping of the errors, and resolving author names for a work (M3.3).
- Persisting works or editions. Nothing is saved on view (CLAUDE.md hard rule).
- Series lookup. Series is local data, not an Open Library call.
- Genre filtering and subject-to-genre mapping. The search query is passed verbatim, so M3.4 can send `subject:"..."`.
- The `maintenance.cleanup` job. This spec only provides `deleteExpired()`.
- Negative caching of misses, retries and circuit breaking.

## Data model

New Prisma model (UUID v7 id generated by the app, as in SPEC 06):

```prisma
model ExternalCache {
  id        String   @id
  key       String   @unique
  payload   Json
  expiresAt DateTime @db.Timestamptz(3)
  createdAt DateTime @default(now()) @db.Timestamptz(3)

  @@index([expiresAt])
}
```

Cache keys: `ol:search:<sha256 of "<normalized query>|<page>">`, `ol:work:<OL…W>`, `ol:editions:<OL…W>:<lang or all>`, `ol:isbn:<normalized isbn>`, `ol:author:<OL…A>`. Cached payloads are the mapped Verso types, not raw Open Library JSON.

External types (in `apps/api/src/infra/catalog/catalog-provider.ts`):

```ts
type EditionFormat = 'PAPERBACK' | 'HARDCOVER' | 'EBOOK' | 'OTHER';

type WorkSearchResult = {
  olWorkKey: string; // "OL45883W"
  title: string;
  authors: { olAuthorKey: string; name: string }[];
  firstPublishYear: number | null;
  coverUrl: string | null;
  editionCount: number;
  languages: string[]; // ISO 639-1, only known codes
};

type ExternalWork = {
  olWorkKey: string;
  title: string;
  subtitle: string | null;
  description: string | null;
  firstPublishYear: number | null;
  coverUrl: string | null;
  authorKeys: string[]; // names are resolved with getAuthor
  subjects: string[]; // raw Open Library subjects
};

type ExternalEdition = {
  olEditionKey: string;
  olWorkKey: string | null;
  title: string;
  isbn10: string | null;
  isbn13: string | null;
  publisher: string | null;
  publishYear: number | null;
  language: string | null; // ISO 639-1
  pageCount: number | null;
  format: EditionFormat;
  coverUrl: string | null;
};

type ExternalAuthor = {
  olAuthorKey: string;
  name: string;
  bio: string | null;
  birthYear: number | null;
  deathYear: number | null;
  photoUrl: string | null;
};
```

Conventions:

- Keys are bare (`OL45883W`), never `/works/OL45883W`. Malformed keys throw `CatalogNotFoundError` without a network call, so a caller cannot inject path segments.
- Covers: `https://covers.openlibrary.org/b/id/{id}-M.jpg` (authors: `/a/id/`). Missing or non-positive cover id means `null`.
- Search returns one page of 20 results as an array. Fewer than 20 means the last page.
- `listEditions` fetches up to 100 editions in one call and filters by `language` in the provider, because Open Library has no language filter. Open Library language codes (`/languages/spa`) map to ISO 639-1 through a small table; unknown codes become `null`.
- Open Library `description` and `bio` can be a string or `{ type, value }`. Both map to a string.
- ISBN input is normalized (hyphens and spaces removed, `x` uppercased). Anything that is not 10 or 13 characters returns `null` without a call.
- Errors: `CatalogNotFoundError` for a 404 or malformed key. `CatalogUnavailableError` for timeout, network failure, 429, 5xx, an unexpected status or a response that fails Zod validation. `getEditionByIsbn` returns `null` on 404 instead of throwing.
- Env: `OPEN_LIBRARY_CONTACT`. Default `dev@verso.local` outside production. Required and non-empty when `NODE_ENV=production`.

## Implementation plan

1. Record fixtures: with `curl` and a generic User-Agent, fetch search for "Pedro Páramo", the work, its editions, one ISBN and the author. Trim to the fields the mappers use and save under `apps/api/src/infra/catalog/fixtures/`. Verify: files are small and contain no personal data.
2. Create `catalog-provider.ts` (interface, types, `CATALOG_PROVIDER` token), `catalog-errors.ts`, and `catalog-env.ts` with unit tests (default in dev, required in production). Update `.env.example` comment for `OPEN_LIBRARY_CONTACT`. Verify: `pnpm --filter api test`.
3. Add the `ExternalCache` model and migration. Create `external-cache.ts` (`ExternalCacheStore`), `external-cache.repository.ts` (`get`, `set` with TTL upsert, `deleteExpired`) and `in-memory-external-cache.ts`. Integration test on real Postgres. Verify: `pnpm db:migrate`, then `pnpm --filter api test`.
4. Create `open-library-mappers.ts` with Zod schemas and pure mapping functions (key, cover, year, language, format, description). Unit tests against the fixtures. Verify: `pnpm --filter api test`.
5. Create `open-library.provider.ts`: HTTP wrapper with injectable `fetch`, 8 s `AbortSignal.timeout`, User-Agent, error mapping, then the five methods wrapped in a fail-open cache helper. Unit tests with a fake `fetch` and `InMemoryExternalCache`. Verify: `pnpm --filter api test`.
6. Create `in-memory-catalog.provider.ts` (seedable fake) with a unit test, and `catalog-infra.module.ts`. Import the module in `AppModule`. Verify: the API boots and the existing tests pass.
7. Update `ARCHITECTURE.md` §7, tick M3.1 and add the M3.2 note in `ROADMAP.md`. Run `pnpm lint && pnpm typecheck && pnpm test`.

## Acceptance criteria

**Provider**

- [ ] `searchWorks("Pedro Páramo", 1)` against the fixture returns at least one result with `olWorkKey`, title, authors, `firstPublishYear` and a `coverUrl` built from a cover id.
- [ ] `searchWorks` with an empty or whitespace query returns `[]` and makes no fetch call.
- [ ] `getWork`, `listEditions`, `getEditionByIsbn` and `getAuthor` map their fixtures to the types above, including string and `{ type, value }` descriptions.
- [ ] `listEditions(key, { language: 'es' })` returns only Spanish editions. Without `language` it returns all.
- [ ] Every request sends `User-Agent: Verso/1.0 (<OPEN_LIBRARY_CONTACT>)` and an abort signal with an 8000 ms timeout.
- [ ] `getEditionByIsbn` returns `null` on a 404 and for a malformed ISBN (no fetch call).
- [ ] A 404 on work or author throws `CatalogNotFoundError`. A malformed key throws it with no fetch call.
- [ ] A timeout, network error, 429, 500 and an invalid JSON shape each throw `CatalogUnavailableError`.

**Cache**

- [ ] A second identical call hits the cache: the fake `fetch` is called once.
- [ ] Search entries expire after 1 day. Work, editions, ISBN and author entries expire after 30 days (checked through `expiresAt`).
- [ ] An expired entry is ignored and refetched.
- [ ] A cache read or write error is logged and the call still returns data from Open Library.
- [ ] A cached payload that fails Zod validation is treated as a miss.
- [ ] Errors from Open Library are not cached.
- [ ] `ExternalCacheRepository` on real Postgres: `set` upserts by key, `get` ignores expired rows, `deleteExpired` removes only expired rows and returns the count.

**Wiring and docs**

- [ ] `InMemoryCatalogProvider` can be seeded and replaces `CATALOG_PROVIDER` in a Nest test module with `overrideProvider`.
- [ ] In production, boot fails with a clear message if `OPEN_LIBRARY_CONTACT` is empty. In development it boots with the default.
- [ ] No test hits the network.
- [ ] The new migration is forward-only and creates only `ExternalCache`.
- [ ] No email or real contact value appears in the repo or fixtures.
- [ ] `.env.example` documents `OPEN_LIBRARY_CONTACT`.
- [ ] `ARCHITECTURE.md` §7 mentions typed errors, fail-open cache and the env var.
- [ ] M3.1 is ticked and M3.2 carries the `ExternalCache` note in `ROADMAP.md`.
- [ ] `pnpm lint && pnpm typecheck && pnpm test` pass.

UI states: N/A, this spec touches no screen or component.

## Decisions

- **Yes:** create `ExternalCache` here. M3.1 needs a real cache and the table is not in M3.2's list. Doing it later would leave the cache untested.
- **Yes:** contact in env `OPEN_LIBRARY_CONTACT` with a dev default, required in production. The repo is public, so no real email is committed.
- **No:** require the contact in dev and test. It adds friction with no benefit.
- **Yes:** fail-open cache. A Postgres hiccup should not break search. Errors are logged.
- **No:** fail-closed cache or returning `null` and empty arrays on errors. The first couples availability to the cache. The second hides outages from callers.
- **Yes:** two typed errors. M3.3 maps them to stable problem+json codes without parsing messages.
- **Yes:** record fixtures once from the real API and commit them trimmed. Mappers are built against the real shape, and tests never use the network.
- **No:** hand-written fixtures. They can drift from the real response.
- **Yes:** cache the mapped Verso types, validated on read. Stored rows stay small, and a mapper change that invalidates old rows becomes a cache miss, not a crash.
- **Yes:** `ExternalWork` carries `authorKeys` only. The work endpoint costs one Open Library call per method, and M3.3 resolves names through `getAuthor`, which is cached for 30 days.
- **Yes:** external types live in `infra/catalog`. API DTOs go to `packages/shared` in M3.3, where the contract is defined.
- **Yes:** `listEditions` filters by language in the provider. Open Library cannot filter server-side.
- **No:** `getSeries` in `CatalogProvider`. Series is local data (§5.3).
- **No:** negative caching, retries, circuit breaker. About 5 users and one instance do not justify them.
- **Yes:** `ExternalCacheStore` interface plus a Prisma implementation. Provider unit tests use the in-memory fake, and the Prisma class is tested on real Postgres, so Prisma is never mocked.
- **Yes:** wire the module into `AppModule` now. M3.3 can inject `CATALOG_PROVIDER` without touching infra. It makes production env validation fail at boot.

## Risks

| Risk | Mitigation |
| ---- | ---------- |
| Open Library response shape differs from what the mappers expect, or changes later | Zod validation turns a bad shape into `CatalogUnavailableError`, not wrong data. Fixtures come from the real API |
| Open Library is slow or down | 8 s timeout, 30-day cache for reads, typed error for M3.3 to surface |
| More than 100 editions of a popular work are cut off | Accepted for F1. Paging can be added to `listEditions` later without changing callers |
| Stale cache after a mapper change (up to 30 days) | Payloads are validated on read. A shape change is a miss. A semantic change needs a manual `DELETE` of the `ol:*` keys |
| Unknown Open Library language codes map to `null` | `null` is kept in unfiltered lists. The mapping table is extended as cases appear |
| Real contact email accidentally committed | Env only. Fixtures are recorded with a generic User-Agent |

## What is **not** in this spec

- `@nestjs/throttler` and any rate limit (M3.0).
- Catalog tables other than `ExternalCache`, and any persistence of works or editions.
- Endpoints, DTOs, controllers or any web change (M3.3 and later).
- Series, genre mapping and genre filtering.
- The cleanup job, negative caching, retries.
